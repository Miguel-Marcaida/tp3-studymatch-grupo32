Startup: StudyMatch. (Origen IFTS 16) IFTS 29 · Equipo 32 Bloque: Perfil y búsqueda · S13-A

StudyMatch.

“Conectamos estudiantes para estudiar juntos.”

StudyMatch es una red que conecta estudiantes según sus materias, intereses, necesidades y disponibilidad.

Necesidad que Resuelve

Facilita encontrar compañeros de estudio que compartan intereses, horarios y modalidades compatibles, evitando que los estudiantes tengan que buscarlos manualmente de forma desorganizada.

💡

Alcance pedagógico: Modelado conceptual de dos propuestas agénticas para el TP3. La aplicación no integra IA en vivo, ni APIs reales, ni backend en producción.

Bloque Completo · Propuesta 1

Buscador Inteligente (R1)

Conexión de estudiantes con condiciones compatibles basada en perfil completo (p ∧ q ∧ r): sentencia original, formalización lógica, beneficio, diagrama de flujo y funcionamiento técnico detallado.

Sentencia & Lógica · R1
Sentencia original (R1):
“Si el estudiante completó tema de estudio, disponibilidad y modalidad, el sistema busca compañeros con esas condiciones compatibles.”

Formalización Lógica:

  • p = El estudiante completó tema de estudio
  • q = El estudiante completó disponibilidad
  • r = El estudiante completó modalidad
  • Condición lógica: p ∧ q ∧ r (conjunción estricta: los tres datos completos simultáneamente).
⚡ Propuesta Agéntica 1

Asistente Buscador Inteligente

Un agente asistente que recibe el perfil del estudiante, valida que los tres datos requeridos estén completos (p ∧ q ∧ r) y, al cumplirse la condición, consulta la base de datos de perfiles de StudyMatch para devolver compañeros con intereses y horarios compatibles.

✨ Beneficio: Facilita encontrar compañeros para estudiar de forma rápida y evita que los estudiantes tengan que buscarlos manualmente de forma desorganizada. Ahorra tiempo y optimiza la compatibilidad según materias, horarios y modalidad.

Mecanismo Concluyente de R1:

  • Herramienta consultada: Base de datos de perfiles de StudyMatch.
  • Resultado esperado: El sistema devuelve una lista de compañeros compatibles para que el estudiante pueda elegir.
  • Intervención humana: El estudiante decide personalmente con quién desea conectarse de la lista presentada.

🔍 Clic para ampliar
1) Datos de entrada

Tema de estudio, disponibilidad horaria y modalidad (presencial / virtual).

2) Decisión

El agente comprueba si los tres datos están completos (p ∧ q ∧ r).

3) Acción propuesta

Si están completos, consulta la base de datos de perfiles de StudyMatch y busca estudiantes con condiciones compatibles.

4) Herramienta necesaria

Base de datos de perfiles de StudyMatch (acceso de consulta).

5) Resultado esperado

El sistema devuelve una lista de compañeros compatibles para que el estudiante pueda elegir.

6) Excepciones y casos límite
  • Falta algún dato: Se deriva de inmediato al Flujo 2 (Asistente de Perfil).
  • Sin compañeros compatibles: Se informa al estudiante y se le ofrecen alternativas de ajuste pedagógico y franjas horarias (decisión del grupo).
7) Intervención humana

El estudiante decide con quién conectarse: El agente no realiza emparejamientos automáticos ni envía invitaciones no consentidas; la decisión final de interacción recae exclusivamente en la persona usuaria.

Bloque Completo · Propuesta 2

Asistente de Perfil (R2)

Detección preventiva de datos incompletos (¬p ∨ ¬q ∨ ¬r) y orientación al usuario: sentencia original, formalización lógica, beneficio, diagrama de flujo y funcionamiento técnico detallado.

Sentencia & Lógica · R2
Sentencia original (R2):
“Si falta alguno de esos datos, el sistema solicita completarlo y explica que todavía no puede realizar la búsqueda.”

Formalización Lógica:

  • p = completó tema · q = completó disponibilidad · r = completó modalidad
  • Condición lógica: ¬p ∨ ¬q ∨ ¬r (disyunción: se activa cuando falta al menos un dato obligatorio).
⚡ Propuesta Agéntica 2

Asistente Orientador de Perfil

Un agente que inspecciona los datos ingresados por el estudiante, detecta exactamente cuál o cuáles faltan y solicita completarlos, explicando didácticamente que todavía no puede realizar la búsqueda porque se requieren los tres datos para conectar.

✨ Beneficio: Evita búsquedas vacías o engañosas antes de contar con toda la información necesaria. Orienta al estudiante sobre qué datos le faltan completar y le explica con claridad didáctica por qué aún no se puede realizar la búsqueda.

Mecanismo Concluyente de R2:

  • Herramienta consultada: Formulario de ingreso de datos de StudyMatch. No necesita consultar la base de datos de compañeros (privacidad y optimización).
  • Resultado esperado: El estudiante sabe con precisión qué información falta y puede completarla para continuar.
  • Intervención humana: El estudiante ingresa personalmente los datos faltantes (y puede solicitar orientación tutorial).
Diagrama de Flujo · R2

Proceso Agéntico del Asistente de Perfil (R2 · ¬p ∨ ¬q ∨ ¬r)

Falta al menos un dato = SÍ
ℹ️

Recorrido del Flujo 2: Inicio (perfil con datos faltantes) → Entrada: los tres campos → ¿Falta alguno? → SÍ: identificar el dato faltante → solicitar completarlo y explicar motivo → intervención humana: estudiante ingresa datos faltantes → bucle de reevaluación hacia R1 [Decisión Grupo 32] → fin / reanuda. NO (perfil completo): corresponde al Flujo 1.

🔍 Clic para ampliar
1) Datos de entrada

Tema de estudio, disponibilidad horaria y modalidad.

2) Decisión

El agente verifica si falta al menos uno de los tres datos obligatorios (¬p ∨ ¬q ∨ ¬r).

3) Acción propuesta

Si falta información, identifica los campos incompletos, solicita completarlos y explica por qué todavía no puede realizar la búsqueda.

4) Herramienta necesaria

Formulario de ingreso de datos de StudyMatch. No necesita consultar la base de datos de compañeros (ahorro de cómputo y privacidad).

5) Resultado esperado

El estudiante sabe qué información falta y puede completarla para continuar.

6) Excepciones y casos límite
  • Validación de disponibilidad: Se restringe el formato a desde: hh:mm hasta: hh:mm (ej. 08:00 hasta 12:00), validando horas 00-23, minutos 00-59 y que la hora inicial sea estrictamente anterior a la final (decisión del grupo).
  • Reevaluación de R1: Una vez completados los datos faltantes, el agente vuelve a evaluar R1 automáticamente sin reiniciar el proceso (decisión del grupo).
  • Si los datos están completos desde el inicio, R2 no se activa y continúa directamente con R1.
7) Acción del usuario vs. Intervención humana

Diferenciación conceptual fundamental:

  • Acción del estudiante (acción del usuario): Completar o corregir los campos faltantes (tema, horario, modalidad) en el formulario de la aplicación. Esta acción es imprescindible para que el flujo algorítmico avance y se pueda reevaluar R1, pero es una simple carga de datos por el usuario, sin constituir supervisión ni criterio humano.
  • Intervención humana (Decisión del grupo): La opción de solicitar asistencia, orientación pedagógica o acompañamiento personalizado a un tutor académico humano para definir temas de estudio o despejar dudas. Esta opción fue incorporada explícitamente como una decisión del Grupo 32 (no forma parte de la sentencia original de la regla R2) para asegurar el criterio y la empatía de una persona cuando el estudiante lo requiera.
Extensión Arquitectónica

Decisiones Propias del Grupo 32

Distinción explícita de los supuestos y decisiones agregadas por el equipo que NO están definidos por las sentencias originales R1 ni R2:

Decisión 1

Volver a evaluar R1

Después de que el estudiante completa los datos faltantes en R2, el agente verifica nuevamente si los tres datos están completos para enlazar automáticamente con la búsqueda de R1 sin requerir recargar la página.

Decisión 2

Sin coincidencias

Si la base de datos de perfiles no encuentra compañeros compatibles con esas condiciones, el sistema informa al estudiante y le ofrece alternativas (por ejemplo, sugerir ampliar franjas horarias o derivar a orientación humana).

Decisión 3

Disponibilidad inválida

El sistema valida el formato horario ingresado; si detecta una estructura inválida, informa el error y solicita corregirlo antes de evaluar la completitud del perfil.

Decisión 4

Elección de compañeros

El sistema no empareja ni envía invitaciones de manera arbitraria; el estudiante decide personalmente con quién desea conectarse a partir de la lista de resultados compatibles (intervención humana decisiva).

Decisión 5

Tutor académico en R2 y diferenciación conceptual

En R2 se diferenció explícitamente la acción del estudiante (completar los datos faltantes en el formulario para que el flujo avance) de la verdadera intervención humana (revisión y criterio de una persona). Como decisión propia del Grupo 32, se añadió la opción de que el estudiante pueda solicitar orientación a un tutor académico cuando tenga dudas para definir su perfil.

Decisión / Caso límite Criterio adoptado por el Equipo 32 Justificación pedagógica y técnica
Reevaluación de R1 Una vez completados los datos faltantes en R2, el agente reevalúa automáticamente la condición de R1. Evita fricciones y no obliga al usuario a reiniciar o recargar manualmente la página.
Búsqueda sin coincidencias Si no hay perfiles compatibles, el agente informa amablemente y sugiere alternativas de ajuste. R1 no define qué hacer ante cero resultados; el equipo diseñó una respuesta guiada constructiva.
Validación de disponibilidad Restringe formato a desde: hh:mm hasta: hh:mm comprobando h_ini < h_fin. Garantiza coherencia de datos previa a la búsqueda y previene incongruencias temporales.
Selección de compañeros El sistema presenta compatibilidades, pero la conexión final siempre la decide el estudiante. Preserva la autonomía del usuario y evita emparejamientos forzados o intrusivos.
Orientación con tutor académico en R2 Se incorpora la opción de pedir asistencia a un tutor académico ante perfiles incompletos. Diferencia la simple acción de carga del usuario de una verdadera intervención humana de criterio y orientación pedagógica.
⚠️

Aclaración Importante sobre la Disponibilidad Horaria

La restricción de caracteres y formato de disponibilidad (desde: hh:mm hasta: hh:mm, por ejemplo 08:00 hasta 12:00) es una propuesta adicional de diseño del grupo y no una condición contemplada por las sentencias originales de R1 ni R2.

Asimismo, se determinó que no alcanza únicamente con validar caracteres alfanuméricos: el sistema debe comprobar de forma lógica que las horas y minutos sean válidos (formato de 24 horas entre 00:00 y 23:59) y verificar que la hora inicial sea estrictamente anterior a la hora final (por ejemplo: 08:00 hasta 12:00 es válido; 25:00 o 14:00 hasta 09:00 son catalogados como inválidos).
